# AM PM

A restaurant website built with Django: a menu with filters, a session cart with delivery orders, and table reservations on a floor plan with an email confirmation. I wrote it in December 2023 as my second-year project for the Object-Oriented Programming in Python course; the interface is in Ukrainian.

## Features

- Menu grouped by category, with search by name, a category filter and minimum/maximum price filters.
- Product page with a description and reviews. A signed-in user can leave one review per product with a 0-5 rating, and their own review is listed first.
- Registration (username, email, password) and login, using a custom user model `Client` based on `AbstractUser` with a unique email.
- Cart stored in the session: add items from the menu or the product page, increase, decrease or remove them, and see the total.
- Checkout with delivery address, phone number (the browser checks the `+380XXXXXXXXX` format), full name and delivery time. If the delivery time is less than an hour from now, the server sets it to now + 1 hour. The order is saved with one line per product (quantity and line price), and the confirmation page shows the total.
- Table reservation: choose a date (past dates are rejected), then pick one or more tables on a floor plan built from `Table` records (position and size in percent, rectangular or oval, labelled with the seat count). Tables already booked for that date are faded out and cannot be selected, and the server checks availability again before saving.
- After a reservation, an HTML confirmation email is sent to the address entered in the form through Django's SMTP email backend.
- Django admin for categories, products (filter by category), reviews, clients, orders (line items shown inline), tables and reservations (listed with their table numbers).

## Tech stack

- Python 3.10, Django (the project was started on 3.0.14; the last migration was generated by 5.0)
- SQLite
- Django templates, plain CSS, and one small vanilla JavaScript file for selecting tables
- Pillow, which Django needs for the `ImageField`s

## Getting started

The repository has no requirements file. Django 5.0 matches the last migration, and Pillow is required for the image fields.

```bash
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install "django==5.0.*" pillow
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

`db.sqlite3` is not in the repository; `migrate` creates an empty one. Open http://127.0.0.1:8000/admin/ and add:

- categories (the icon is optional) and products. Give every product an image: the menu links to a product only through its image, and the product and cart pages fail without one.
- tables. The coordinate and size fields are percentages of the floor plan.

Email: the SMTP settings at the end of `restaurant/settings.py` (`EMAIL_HOST`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `DEFAULT_FROM_EMAIL`) are empty, and the sender address is hard-coded in `send_reservation_email` in `store/views.py`. Fill them in for your mailbox to send real email, or set `EMAIL_BACKEND = "django.core.mail.backends.console.EmailBackend"` to print the email to the terminal instead. With the SMTP settings left empty, the reservation is saved and then the request fails at the email step.

The menu is at http://127.0.0.1:8000/. The cart, checkout and reservations need a signed-in user.

## Project structure

```
restaurant/          settings and root URL config
store/models.py      Category, Product, Review, Client, Order, OrderItem, Table, Reservation, ReservedTable
store/views.py       menu, product, auth, cart, checkout and reservation views
store/admin.py       admin configuration
templates/           base layout, store pages, reservation email template
static/store/        CSS, navigation icons, reservation.js (table selection)
static/admin/        copy of Django's admin static files
```
